day 6
Linux is more than just a place where you type commands.
There's a lot happening behind the scenes.
As I continue my DevOps learning journey, I'm taking time to understand Linux beyond memorising commands.
One of the things I've been learning is Linux distributions and how Linux works internally.

First, what exactly is a Linux distribution?
You probably know some of these names:

- Ubuntu
- Kali Linux
- Debian
- Fedora
- Arch Linux
- Amazon Linux

They are all Linux distributions.
Think of it like Toyota producing different vehicles: Camry, Hilux, Prado and Highlander.

They belong to the same family, but each has its own design and purpose.

Linux distributions work in a similar way. They share the Linux kernel but come with different tools, software, configurations and intended uses.

For example:

- Ubuntu: A great starting point for beginners, developers and DevOps engineers.
- Kali Linux: Built for penetration testing and security assessments.
- Debian: Well known for stability and reliability.
- Fedora: Popular for its newer technologies.
- Arch Linux: Gives users more control and customisation.
- Amazon Linux: Designed for use within AWS environments.

For our DevOps learning journey, Ubuntu will be our primary Linux distribution because of its documentation, community support and compatibility with popular DevOps tools.

But here's another important thing I learned:
Ubuntu is Linux. It is not something separate from Linux.

Ubuntu is one of the distributions built around the Linux kernel.

Now, let's go a little deeper.
How does Linux actually work?

A Linux system has different components that work together:

1. Hardware: The physical parts of your computer, such as the CPU, RAM and storage.
2. Kernel: The core of the operating system. It manages hardware, memory, processes and other system resources.
3. Shell: The interface that interprets the commands you enter.
4. System Utilities: Tools that help you manage files, directories and other system tasks.

Here's a simple example.
Imagine opening your Ubuntu terminal and asking Linux to list the files inside a directory.

You enter a command.

Your shell interprets it and starts the appropriate program. That program requests the necessary information from the operating system through the kernel, and the results are displayed in your terminal. Everything happens through different components working together.

One important distinction to remember:

The shell is NOT the kernel.

They are two different things.

- The shell interprets your commands.
- The kernel manages system resources and provides services to programs.
- The terminal gives you a place to interact with the shell.

Why does this matter for DevOps?

Because working with Linux goes beyond knowing commands.
